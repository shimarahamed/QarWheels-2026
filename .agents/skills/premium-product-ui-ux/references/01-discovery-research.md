# 01 — Discovery and UX research

**Use for:** research. Each rule is a context-sensitive heuristic unless a formal standard is explicitly named; do not apply mechanically.

### UX-001 · Define the core job

- **Apply:** Write the user's desired outcome as a job-to-be-done before proposing a page.
- **Verify:** The brief names a concrete task and success condition, not a vague aesthetic.

### UX-002 · Map primary segments

- **Apply:** Separate first-time, returning, expert, and accessibility-dependent user needs when they materially differ.
- **Verify:** Flows identify which segment each decision serves.

### UX-003 · Locate the critical journey

- **Apply:** Draw the shortest credible path from entry to task completion before polishing secondary pages.
- **Verify:** The main journey is testable end-to-end.

### UX-004 · List user questions

- **Apply:** Capture what users need to know at each decision and surface that information before commitment.
- **Verify:** A participant can act without searching for hidden conditions.

### UX-005 · Distinguish evidence from guess

- **Apply:** Mark observed problems, analytics findings, and design hypotheses separately.
- **Verify:** Each recommendation has an evidence level or a test plan.

### UX-006 · Interview for behavior

- **Apply:** Ask about the last real attempt and observed workarounds rather than opinions about imagined features.
- **Verify:** Notes contain concrete episodes and obstacles.

### UX-007 · Study failure cases

- **Apply:** Research abandonment, errors, slow networks, and help requests, not only successful happy paths.
- **Verify:** Journey map includes at least three plausible failures.

### UX-008 · Define decision metrics

- **Apply:** Choose a leading task metric and a guardrail before changing the interface.
- **Verify:** Measurement plan has denominator, baseline, and ownership.

### UX-009 · Prioritize by impact

- **Apply:** Rank issues by user harm, reach, frequency, and remediation effort rather than visual novelty.
- **Verify:** Critical blockers precede stylistic changes.

### UX-010 · Validate with target users

- **Apply:** Test representative tasks with actual users when practical; do not equate internal preference with evidence.
- **Verify:** Findings record observed behavior and unresolved questions.
